# ML-Based DVFS Optimization for HPC Systems

This repository contains the notebook-based experimental work for predicting and optimizing the energy-performance behavior of CPU frequency scaling configurations on ARM and x86 platforms.

The current phase covers:

- exploratory analysis of the PPDS M/M/1 experimental dataset;
- data-integrity checks and configuration-aware outlier detection;
- preprocessing and surrogate-model development;
- Energy-Delay Product (EDP) evaluation and configuration selection.

## Notebooks

1. **Exploratory data analysis**  
   Examines the ARM and x86 datasets, variables, distributions, configurations, and relationships between utilization, frequency, performance, and power.

2. **Data integrity and outlier detection**  
   Checks physical and experimental consistency, detects invalid runs, identifies configuration-aware anomalies, and documents correction or exclusion decisions.

3. **Preprocessing, surrogate model, and EDP optimization**  
   Prepares model-ready data, trains and evaluates surrogate models, predicts performance and power outcomes, computes EDP, and selects promising governor configurations.

## Setup

Create and activate a virtual environment, then install the dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
jupyter lab
```

On Windows, activate the environment with:

```powershell
.venv\Scripts\activate
```

## Data

The experimental datasets are not committed to Git because they may be large or restricted. Place the original files under `data/raw/arm/` and `data/raw/x86/`. Store generated model-ready datasets under `data/processed/`.

See [`data/README.md`](data/README.md) for the expected organization.

## Reports and results

Formal reports and presentations belong in `reports/`. Figures, tables, and model metrics generated by the notebooks belong in `results/`.

## Current status

This is the initial notebook-oriented version of the project. Reusable Python modules, automated tests, and reinforcement-learning components can be added after the experimental pipeline becomes stable.
